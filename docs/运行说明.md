# VCIA 实验代码使用说明

## 先看一轮决策演示

下载并解压仓库后，直接用浏览器打开 [离线演示](../examples/admission_walkthrough.html)。每个场景都可以展开查看手写输入、单体筛查结果和全部三种组合。

- **筛查排除了能相互抵消的版本。** VCIA 筛完凑不够两个合格的当前版本，保留存储状态。取消筛查后，节点 `0` 和 `1` 的组合通过验证并提交。
- **排序选出提案，验证决定是否提交。** 同一候选族中，VCIA 按年龄优先选 `[0, 1]`，验证通过。Drift-First 按设计漂移最小选 `[0, 2]`，固定提案验证失败后保留存储状态。

按下文安装后，运行 `python -m pcoc.demo` 可以用仓库的正式决策函数重现同一输出。示例的概率与探针序列是手写的，只用于演示流程。

`COMMIT` 表示演示中的准入通过，未写入节点状态或执行分布式提交。每个批次只有一个独特的手写探针，重复输入仅演示计算与决策分支，不提供独立抽样证据。

## 先确认有哪些运行入口

| 目标 | 配置或入口 |
| --- | --- |
| 主结果，六个排序规则 | `configs/outer_ranking.json`，全量 540 条轨迹 |
| 个体筛查值不值得保留 | `configs/outer_screening.json`，全量 180 条轨迹并存同一冻结候选池的普查结果 |
| 独立验证的贡献与代价 | `configs/outer_audit.json`，包含固定提案验证、精确有限目标、跳过验证和同时验证族 |
| 旧策略、冻结和无保护对照 | `configs/outer_controls.json` |
| 内层预算校准 | `configs/inner_calibration.json` 和 `python -m pcoc.analysis calibrate` |
| 稳健性和迁移 | `configs/robustness.json`、`configs/outer_transfer.json` |
| 本机多进程通讯 | `configs/outer_loopback.json` |
| 100／300 轮 WL 恢复扩展 | `configs/outer_recovery_100.json`、`configs/outer_recovery_300.json`，每套 540 条轨迹，审计预算需按日程重新校准 |
| 原来的数值实验 | `python -m legacy`，含 20 轮主实验、补充机制和 60 轮恢复 |
| 原来的内层 WL 试验与回放 | [Archived WL pilot](../legacy/wl_pilot/README.md)，保留当时的运行和出表命令 |

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
python -m pcoc plan --config configs/outer_ranking.json --job 1:6 --list
python -m pcoc check-data --config configs/outer_ranking.json --data-dir data
```

仓库根目录下的 `data` 放原始 TU ZIP。已有数据可直接放入，或通过 `python -m pcoc fetch --config configs/outer_ranking.json --data-dir data` 获取。`plan` 只显示配置规模和任务号。`check-data` 读取 ZIP 文件，校验成员、CRC 和已登记的 SHA-256。两者均可在实验前运行。

以后开始正式数据生成时，先用内层配置和证据分析确定容忍阈值、裕量、验证预算和回退规则，并登记最终配置。以下命令启动指定任务，输出必须是新目录。

```powershell
python -m pcoc run --execute --config configs/outer_ranking.json --data-dir data --job 1:6 --output runs/ranking-01
python -m pcoc.analysis summarize --runs runs/ranking-01 --output runs/ranking-01-summary.json
```

外层配置默认保留初始设计预算 512 和验证预算 8,192。改变预算会影响后续执行状态，因此闭环数据需要按最终选定的配置重新生成。`run_index.json` 记录失败原因，`manifest.json` 钉住输入和代码，`rounds.jsonl` 含逐轮状态和成本，`checkpoint.npz` 用于检查最后实际执行的模型内容。更多字段见 [Protocol and outputs](protocol.md)。

## 复算摘要数据

运行 `python reproduction/recompute.py` 即可从随仓库附带的逐轮记录复算两项摘要结果。这里使用的是筛查版与 Unscreened 的配对 CPU 实测，以及 VCIA 与 J-Rank 的固定快照回放。Python 模块与历史记录沿用 `pcoc` 和 `PCOC`。
