VCIA decision walkthrough

Fixed, hand-authored cluster probabilities illustrate how the design probe batch guides selection and how a separate verification batch checks the selected composition.

Each proposal chooses two of three peers to use current versions. The other peer keeps its stored version. HOLD keeps all three stored versions. The fixed batches repeat the design graph 512 times and the audit graph 8,192 times.

COMMIT denotes an accepted composition in this walkthrough. The demo does not write peer state or execute distributed commit.

Each batch contains one unique hand-authored probe. Repeated inputs illustrate the calculation and do not provide independent-sampling evidence. This walkthrough includes no learner training, benchmark evaluation, or empirical estimate of audit power.

Screening can exclude a cancelling pair

Peers 0 and 1 fail the individual screen. Together their changes cancel, so the Unscreened policy can commit both after audit.
